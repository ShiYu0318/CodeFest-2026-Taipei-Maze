# 北車不迷路 Bar｜台北沒事吧！— 手機端離線 AI 功能規劃

## 專案目標
以「數位平權 × 友善共融」為核心，協助旅客在臺北車站透過語音、文字、拍照與 QR Code，獲得容易理解的室內導航。優先採用非中國團隊開發、可在手機端離線執行的模型；模型授權需逐項確認。

## AI 功能與優先級

| 功能 | 技術選項 | 用途 | 優先級 |
|---|---|---|---|
| 自然語言目的地搜尋 | 同義詞字典、規則式 NLP；選配 Gemma 3 270M | 理解「我要去高鐵」等需求 | P0 |
| 多語目的地搜尋 | 多語字典；選配 EmbeddingGemma 300M | 中文、英文、越南文名稱對應同一設施 | P0 |
| 導航指令易讀化 | 結構化模板 | 將路線轉為大箭頭、地標與簡單文字 | P0 |
| 迷路自救與重新定位 | QR Code + Graph + 狀態機 | 重新掃碼、重新規劃路線 | P0 |

## 建議模型
- **Whisper Tiny / Base（OpenAI）**：離線語音辨識，可透過 whisper.cpp 整合手機端。
- **Gemma 3 270M（Google）**：小型語言模型，可嘗試目的地與條件解析；屬開放權重、Gemma 專屬授權，非一般 OSI 開源授權。
- **EmbeddingGemma 300M（Google）**：多語文字向量檢索；小型 POI 資料庫不一定需要。
- **MobileNetV3（輕量視覺架構）**：設施圖示分類，需準備資料並訓練／微調。
- **OCR**：可研究 Tesseract 等開源方案；需實測繁體中文、英文及手機效能。

## 建議系統流程
1. 使用者以文字、語音、拍照或 QR Code 提供資訊。
2. Whisper／OCR 將語音或指標轉成文字（選配）。
3. NLP 將文字對應到已知 POI 與路線限制；不確定時要求確認。
4. Graph Routing Engine 依已驗證路網與無障礙硬性限制規劃路線。
5. 顯示逐步圖像、地標提示及預先產生的離線多語語音。
6. 迷路時重新掃描 QR Code，更新位置並重新規劃。

## 24 小時 MVP 建議
**必做：** QR 定位、Graph 路徑規劃、無障礙限制、規則式多語目的地搜尋、易讀指引、迷路重掃。

**有餘力再做：** Whisper Tiny 語音搜尋、OCR 指標辨識、路線理解難度排序與測試。

**暫緩：** Ollama 伺服器、通用 LLM 聊天、VLM 視覺定位、RL 導航。

## 重要限制
- OCR 讀到某個出口標誌，**不代表使用者就在該出口**；仍以 QR Code 作為定位錨點。
- LLM 不得自行產生不存在的通道、出口或無障礙設施；導航事實一律由已驗證 Graph 提供。
- 所有模型需確認手機端部署、授權、語言效果與實際延遲；「離線」需在飛航模式下實測。
- 未經場站驗證的路網只能作為競賽示範，不宣稱可直接用於真實公共安全導航。

**核心定位：離線多模態輔助 × 認知友善室內導航。**

### 規則搜尋的能力與限制

- 原型提供中、英、越、印尼、泰、韓、日的種子 alias，全部保留 draft 及 team-authored 來源；不是七語校對完成證明。prototype UI 明示啟用草稿，search core 在未開 prototype 時只接受 approved alias。
- 真實站圖只查詢現有點位，點選後切換到其樓層並選取標點；不會建立不存在的高鐵／出口，也不由座標推測走道路徑。
- `restrom`／`toielt` 只提供需確認的建議。數字／字母編號、QR／節點 ID 不被修成一般設施；不同概念的同詞或同距離候選不擅選。
- 「不要樓梯」追加 excludedEdgeTypes=[stairs]，不自動認定使用者使用輪椅；「無障礙廁所」另要求設施證據與 stepFree。現有較強限制及本次不可用設備不能被搜尋解除。
- 原型站圖尚無已核對設施可及性，不能只憑名稱裡「無障礙」就當作 true。合成測試廁所的 accessible_facility=true 是明確測試假設，並非現場證據。
- 最近排序目前要求澄清，不使用直線距離或過時定位冒稱最近；需完成新確認起點 token 與走道路網後再加入。
- 不支援的否定、比較、複數目的地與剩餘條件要求澄清；輸入及正規化後皆限制 80 個 Unicode code points。
- 查詢只留在目前頁面的記憶體，不上傳、不保存歷史、不呼叫遠端 LLM／翻譯／向量 API。

### 可操作的測試

1. `/station-map` 輸入 `toilet`、`nhà vệ sinh`、`ห้องน้ำ` 等，選既有設施查看樓層。
2. 輸入 `restrom`，確認顯示錯字建議且不自動選擇。
3. 輸入「不是廁所」「廁所要便宜」「nearest restroom」，確認不直接提供符合需求的導航宣稱。
4. `/navigation-demo` 選 TEST-A 定位，再搜尋 `accessible toilet`；確認目的地後重新確認位置，驗證路線採用合成測試電梯。
5. 切換易讀模式並開始導航，確認下一步、到層確認、迷路重定位與抵達流程；此流程只驗證合成資料，不代表北車實地導航。
自動測試使用 `cd app && npm test`；lint 與 build 分別為 `npm run lint -- --no-fix`、`npm run build`。瀏覽器點擊、版面及真機語音／掃碼未經驗證時，保持 not_run。
