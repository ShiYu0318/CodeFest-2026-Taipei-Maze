# 集合點分享與持續掃碼開發指南

> 最新整合：正式地圖已新增持續掃碼流程，請先看 [正式地圖持續掃碼開發指南](./正式地圖持續掃碼開發指南.md)。以下保留合成 Graph／分享卡的開發契約，不等於正式北車步行路線已完成。

更新：2026-11-07。這一版只提供合成場景的分享與導航流程；沒有核准任何真實北車等候地點，也不提供朋友即時位置追蹤。

## 使用流程

1. 在 `/navigation-demo` 先選目的地與通行需求。
2. 城市通提供新版 bridge 時，按「開始持續掃描（有效碼自動更新）」。相機保持開啟，畫面同時顯示目的地、樓層與下一步。
3. 每掃到不同的有效定位碼，以新 anchor 更新上次確認位置，保留目的地與自己的通行需求，失效舊路線並重算。
4. 掃碼不等於知道手機朝向；新路線先顯示地標與朝向，再由使用者確認開始。到層、下一步與抵達在同一原生掃描畫面操作。
5. 重複影格不重算；若需要再次確認同一個碼，按「重新讀取同一碼」，不必關閉相機。
6. 關閉相機後回到網頁，保留最後有效位置與目的地。開始掃描但取消且沒有新定位時，保留原任務；錯碼及集合分享連結不變更起點。

一般瀏覽器或舊宿主沒有 `qr_scan_session` 能力時不假裝有常駐相機；仍可用明確標示的合成測試點，或舊宿主的單次掃碼備援。

## 固定集合點

- 目前只有 `mp_a`、`mp_b` 兩個合成白名單，對應 `qr_a`／`qr_b2_lift` 與獨立 `meeting_point` POI。它們不等於真實通道或電梯門前可以等候。
- 分享只在有效已確認 anchor 且位置／POI 同節點時開放。使用者需勾選仍在此處等候，生成連結不重寫原掃碼時間。
- 連結指向使用者指定的正式入口 `http://home.yoyo899843.com:8000/meet`，只帶型別、版本、場域、點位、graph major 與確認時間，不含姓名、帳號、電話、GPS 或接收者偏好。
- `/meet` 可以先看集合卡及合成局部圖，不要求相機或帳號。卡片沒有取得 B 的起點，不顯示 A 在線、已讀或持續移動。
- B 明確選擇集合目的地後，清除原起點並等待 B 掃自己的 QR；保留 B 的語言呈現／通行限制與本次不可用設備。A 的確認時間與位置不寫成 B 的定位。
- 開連結不自動覆寫同一導航頁的目的地；先顯示待確認集合卡。離開未完成任務時有確認，取消不離開原任務。
- 同點仍需確認抵達；找不到路線不解除無階梯或排除條件。

`meeting_points` 為原型新增資料，見 `app/src/meeting/meeting-points.json`；名稱與等待說明引用 graph.messages，位置從 anchor／POI 推導。未建立真實 field_verified 資料包，不把原站圖每個 marker 都當成集合點。

## 連結與時間規則

`MeetingLink` 上限 2048 UTF-8 bytes，僅接受精確白名單參數、唯一欄位、相容版本、合法點位與有效含時區 ISO 日期。拒絕重複／未知參數、其他 origin／path、userinfo、hash、無效日期與日曆 rollover。不開外部 URL、不由連結提供座標、HTML 或指令。

現在明確允許的原型 origins：正式 HTTP 入口、`http://127.0.0.1:8082`、`http://localhost:8082`；HTTPS 正式化需另行設定核准 origin。原提案的 HTTPS 是目標，不會把目前 HTTP 稱為 HTTPS。

工程預設：超過 30 分鐘提示時間過舊，超前本機時鐘 5 分鐘提示時間異常。門檻是本次實作決定，非官方規定；時間可被改寫、也沒有伺服器驗證。這不是身份驗證、過期控制或撤銷能力，固定連結不能跟著分享者移動。

分享／複製由使用者按鈕觸發；HTTP 或不支援 API 的環境可能無法使用 Web Share／剪貼簿，保留完整唯讀文字供手動複製。系統分享結束不代表對方收到；不自動替使用者傳訊給任何人。

## 新版原生協定

舊 `qr_code_scan` 仍保留，不以循環重開舊掃碼頁模擬連續模式。新協定名稱 `qr_scan_session`，先以 `capabilities` 確認 `continuous=true`、`protocol=1`，之後用 `start`／`update`／`stop` 管理同一個 scanner。

每一段相機工作使用隨機 32 位十六進位 sessionId；事件含遞增 seq。前端忽略舊 sessionId、重複或倒退 seq；停止後不採用晚到掃描。能力探測本身不開相機。

- Native `detected`：只有 payload，不宣稱位置已有效。Web 以既有 QR parser／graph 查核後才更新 session。
- Native `action`：帶畫面上那一則 guidanceToken。Web 以 route revision／phase／step 檢查，不拿舊按鈕推進新路線。
- Native 在掃到 QR 或送出下一步時立即消耗／停用按鈕，收到更新指引才重開；guidanceVersion 遞增，舊 update 不可重新啟用舊指令。
- 相機與指引區分開建置，更新文字不建立另一個 MobileScannerController，也不因每張碼重開相機。
- App 進背景暫停相機，回前景再依頁面狀態恢復；離開掃碼頁釋放 controller。這是實作行為，背景／權限切換仍需真機驗證。

Native handler 僅接受主 frame 與上列精確 origins，拒絕其他頁面。所有新指令文字有型別與長度限制，使用普通 Text，不執行網頁送來的程式。

## 人工驗證清單（尚非 PASS）

| 情境 | 預期 |
| --- | --- |
| 手機持續對準同一碼 | 不反覆重算、不重開相機；可按同碼重讀 |
| 先選廁所，再掃 A／B／A | 目的地不變，每次有效新點重算 |
| 掃新 QR 同時點舊下一步、快速連點 | 不能跳過新朝向或多走步驟 |
| 錯碼、分享碼、不相容站點 | 不中斷相機、不偽造位置 |
| 無階梯＋電梯停用 | NoRoute，不給樓梯替代 |
| A 產生連結、另一台 B 查看 | 固定集合點相同，B 尚未定位 |
| B 接受後掃自己的碼 | 起點是 B，新 route 仍到集合目的地 |
| 取消分享、剪貼簿失敗、HTTP | 保留卡片並可手動複製 |
| 應用背景、權限拒絕、返回、關閉 | 相機資源及任務狀態正確恢復 |

真實等候區核對、七語頁面校對、預生成音檔、首次離線、Universal Links／App Links、真機相機與 Android 建置／操作仍未全部驗證。Gemma 本地聊天與語音輸入是下一個獨立工作項，並非這裡已有的功能。

## 正式地圖的地點分享（2026-11-08）

舊的 `/meet` 集合點仍使用合成資料，只供測試。正式地圖另外提供「分享地點」，讓使用者把車站內的真實地點傳給朋友：

- 入口有兩個：設施卡上的「分享地點」，以及路線區有目的地時的「分享目的地」。
- 連結格式為 `https://home.yoyo899843.com/station-map?destination=<地點 ID>&shared=1`（`app/src/station/place-share.mjs`），可用 `VUE_APP_SHARE_ORIGIN` 覆寫網域。連結只帶地點，不帶分享者的位置、時間或路線，所以不是即時位置分享。
- 朋友打開連結後，這個地點會成為他的目的地，路線區顯示「朋友分享的地點……這是固定地點，不是即時位置」。他掃碼定位後，就以自己的位置為起點規劃路線；目的地不在步行路網內時，會照實說明。
- 分享方式：系統分享選單（`navigator.share`）、複製連結；兩者都不支援時，可以手動選取連結。分享訊息附上現場中文名稱與樓層。
- 尚未完成：分享用的 QR Code（需要先審查 QR 產生套件的授權）、城市通 WebView 對 `navigator.share` 與剪貼簿的真機支援。
