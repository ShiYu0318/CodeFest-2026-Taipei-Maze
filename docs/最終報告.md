報告日期：2026-11-08  
作品名稱：北車不迷路  
作品形式：城市通 Flutter App 內的 WebView 微服務網頁  
服務入口：https://codefest.yoyo899843.com/station-map  
實作盤點基準：`719643d`，另含本輪地圖自適應高度調整。資料與測試結果以本文記錄的版本為準。

## 一、作品摘要

「北車不迷路」以台北車站為應用場域，將找設施、確認位置、規劃路線、逐步導引及分享集合地點整合成同一套手機操作流程。使用者可以搜尋起點與終點，或在城市通內掃描定位 QR Code，再透過地圖路線、大方向圖示、沿途設施與上一步／下一步掌握行進方式。

作品主打「易讀設計、圖像化指引」：畫面保留完成任務需要的資訊，較長的方向說明、資料來源與授權收進資訊視窗；提供繁體中文、英文、越南文、印尼文、泰文、韓文及日文七語介面，以及「預設／兒童／長輩」顯示模式。最近可達設施與無障礙路線則讓使用者依當下需求選擇目的地。

目前已交付可部署的網頁、局部圖面步行路網、搜尋與導航核心、自動測試、資料處理工具及開發文件。全站地圖顯示不等同全站路網接通；現地 QR 布設、完整路網、雙平台城市通真機驗收及七語校對仍是落地前的重要工作。

## 二、城市通微服務理念與服務受眾

### 2.1 在既有市民服務入口提供場域服務

城市通微服務讓團隊以網頁承載特定公共服務，透過既有 App 入口使用必要的原生能力。本案採取這個方式，避免要求民眾為一次站內尋路再安裝另一套導航 App。

網頁負責設施搜尋、地圖、路徑計算、操作介面及分享；城市通負責其既有的原生掃碼能力。核心尋路不要求登入、GPS 或通知權限，選配語音功能也保留純文字操作。一般瀏覽器可作為地圖與手動起終點的備援，但不能將瀏覽器操作視為城市通橋接已通過驗證。

依目前開發限制，本輪僅修改 CodeFest 網頁及 QR 產碼端，沒有為新增功能改動 TownPass 宿主。歷史整合 patch 與原生 AI 設計留作參考，不代表原版城市通已具備全部擴充能力。

### 2.2 受眾與具體需求

| 受眾／情境 | 常見困難 | 本案提供的協助 |
| --- | --- | --- |
| 初次到訪者、轉乘旅客 | 不熟悉樓層及通道，難以把站圖轉成下一步 | 起終點搜尋、跨樓層步驟、地圖與箭頭同頁呈現 |
| 急需廁所、電梯等設施的人 | 不知道附近哪一處實際可達 | 設施分類、最近可達與單一「帶我去」入口 |
| 推嬰兒車、行動不便或需要避開階梯的人 | 最短距離不一定符合通行需求 | 無障礙路線硬性過濾，不自動放寬未知條件 |
| 兒童、長輩及需要較低閱讀負擔的人 | 小字、長段說明與操作分散 | 注音／較大字級、圖示、可展開資訊及集中操作 |
| 外籍旅客與非中文母語使用者 | 設施名稱、語言與標示不同 | 七語介面、多語同義詞與本地設施搜尋 |
| 同行者與站務人員 | 集合地點難描述，迷路時難說明位置 | 固定起點／目的地分享、給站務人員看的求助卡 |

上述是設計服務對象，尚未完成各族群的正式使用者研究；不能將設計假設寫成已證實的改善成效。

## 三、應用場景與完整操作流程

### 3.1 已知道自己在哪裡：直接規劃路線

1. 在起點列搜尋並選取目前所在設施。
2. 在終點列搜尋目的地；各樓層選單可以收合。
3. 視需求勾選「無障礙路線」。
4. 按一次「帶我去」，直接計算路線，不要求再次掃碼。
5. 在同一頁查看地圖路徑、方向圖示與上一步／下一步。
6. 最後一步按「我已抵達」，再按「完成行程」。手動確認與實際定位分開記錄。

### 3.2 急找設施：以最近可達完成任務

使用者選擇「廁所」等類別，勾選「最近可達」，按「帶我去」。已有手動起點或 QR 定位時直接沿用；尚無起點時提供定位或手動選擇入口。最近判定使用可通行路徑成本，避免把直線距離最近、實際隔牆或不互通的設施當成答案。

「全部」會保留當前樓層所有設施圖示；選擇特定類別則縮小顯示範圍。導航路徑與起終點標示仍保留。

### 3.3 途中不確定位置：重新掃碼修正

地圖下方提供重新掃描定位。先顯示覆蓋目前頁面的小型提示框，確認後呼叫城市通相機；成功取得有效定位碼後更新位置與路線，取消則保留原行程。現有宿主使用單次掃碼橋接，不能宣稱相機能無限常駐掃描。

QR Code 只確認掃碼當下的位置，不代表系統知道之後每一步的位置或手機朝向。手動切換步驟也不代表使用者已實際走到該處。

### 3.4 與朋友集合及向站務求助

起點與終點各列都有分享入口。朋友收到的是固定地點，開啟後自行設定起點，不會收到分享者的即時位置或完整移動紀錄。求助、取消行程與重新掃描集中在地圖下方，減少操作入口分散。

### 3.5 降低閱讀與語言負擔

使用者可切換七語、兒童注音或長輩字級；小幫手可回答本地設施問題並提供設施卡片。點選建議問題後，其餘建議仍可繼續操作。長篇說明收進可捲動資訊視窗，保留主畫面的地圖與行動按鈕。

## 五、技術架構與引用技術

### 5.1 系統分工

```text
城市通 Flutter 宿主
  └─ WebView：北車不迷路
       ├─ Vue 3：地圖、搜尋、導引、分享、資訊及小幫手
       ├─ SVG：樓層示意、設施、路線與方向呈現
       ├─ 本地 JSON：點位、跨層連線、步行圖、多語詞典
       ├─ 純 JavaScript 模組：搜尋、Dijkstra、條件過濾、狀態管理
       └─ flutterObject 橋接：既有 QR 掃碼能力

GitHub main → self-hosted runner → Docker Compose → nginx → HTTPS 服務
```

正式功能主要位於 `app/`；宿主不另複製進本 repo。既有 Flask 後端保留為測試／診斷用途，核心地圖與路線不需要後端儲存使用者行程。

### 5.2 技術選擇與用途

| 技術 | 使用方式 | 選擇理由 |
| --- | --- | --- |
| Vue 3、Vue Router、HTML／CSS／JavaScript ES Modules | 建立手機 WebView 介面與分離元件 | 沿用既有專案，便於分工與部署 |
| SVG 與本地 JSON | 圖面、點位、樓層、設備及路線資料 | 可控制圖示、縮放及分層顯示，資料可獨立核對 |
| Dijkstra 與最小堆積佇列 | 在通行條件過濾後搜尋最短成本路徑 | 路徑可重現，便於用測試驗證，不依賴生成式模型猜路 |
| Unicode 正規化、多語詞典、Optimal String Alignment | 同義詞、錯字與簡單意圖處理 | 於本地完成有界搜尋，保留否定與限制條件 |
| `flutterObject` JSON 橋接 | 以 `{name, data}` 呼叫 `qr_code_scan` | 沿用城市通協定，室內定位不挪用 GPS |
| Node.js built-in test runner | 核心與元件 renderer 測試 | 讓路網、搜尋、狀態與界面邏輯可重現驗證 |
| Docker、nginx、GitHub Actions | 建置、發布、SPA 路由與服務檢查 | 提供可移交的部署流程與版本追溯 |

目前主流程使用 Dijkstra；A*、多條候選路線與「最快／最容易理解」的完整多目標比較仍是後續工作，不能把提案演算法清單當成全部已實作。

### 5.3 本地問答、串流與語音界線

小幫手的基礎回答由本地資料與規則產生，事件格式包含 `thinking`、`delta`、`done`，介面顯示處理步驟與逐段文字。這是 App／網頁內部事件，不是網路 EventSource；處理摘要只呈現實際執行的查詢工作。

選配裝置端 Gemma 3 1B、LiteRT-LM 與主動語音輸入已有歷史整合設計及相關介面。模型授權、下載來源、檔案雜湊、手機記憶體與速度、麥克風、原生真串流仍需逐項驗證；不能以網頁 Mock 或打字動畫宣稱手機模型已成功運行。本輪不修改宿主，不加入遠端 LLM、翻譯或 TTS API。

### 6.2 資料處理與導航資料包

資料流程為「來源登錄 → 編碼與欄位整理 → 北車子集篩選 → 點位與樓層對應 → 走道與入口建模 → 通行條件標記 → 自動驗證 → 網頁載入」。

點位記錄名稱、類別、樓層及相對座標；路網另記節點、邊、成本、開放狀態、階梯條件、輪椅通行條件、來源與核對層級。同一張圖上看得到兩個設施，不代表兩者之間可通行。只有成功綁定且滿足限制的點位才參與規劃。

## 十、可靠性、安全與隱私設計

- 路線先做通行限制過濾，再求解；找不到路線時保留原因，不以直線或放寬無障礙條件補上。
- 未知可及性不當作安全通行證據。無障礙拒絕可能來自資料不足，不應解讀成現場設施必定不可及。
- 舊掃碼橋接沒有 requestId，同名請求不並行；逾時與遲到回覆需隔離，避免把舊結果當成新定位。
- 手動起點、連結位置、QR 定位與 Demo 清楚區分；只有有效的真實 QR 記錄顯示上次掃碼時間。
- 手動抵達記錄只適用當前行程；更換起終點、通行條件或重新定位後失效，不把目的地寫成新掃碼位置。
- 分享固定地點，不分享即時位置；主流程不要求真實帳號、GPS 或通知。語音僅於主動操作時請求相關能力。
- 執行期不使用遠端 LLM、翻譯或 TTS。所有新增來源須符合專案來源與授權審查要求。
- 離線能力須區分已載入資料、重新開啟與全新安裝；尚未完成全新安裝離線驗收，不承諾所有入口皆可離線。

### 12.2 最長路線候選

以目前預設通行條件，枚舉已綁定點位之間的最短路徑，再取成本最大者：

- 包含示意 QR 點：B1「QR 04 號示意定位點」→ B3「淡水信義線大廳北端電扶梯」，相對成本 2637.9，共 19 個步驟。
- 排除示意 QR 點、便於以設施搜尋：B1「廁所（北側西段）」→ B3「淡水信義線大廳北端電扶梯」，相對成本 2462.9，共 19 個步驟。
- 兩組皆經 B1 → B2 → B4 → B3，使用一般路線；不開啟無障礙條件，也不放行需票閘門。

此處「最長」指現有圖模型中「兩點最短可通行路徑的最大值」，不是刻意繞遠，也不是實際全北車最遠距離。繞經 B4 是目前連線與成本下的模型結果，仍須現地核對。主秀建議採簡短成功情境，19 步路線作為跨層與步驟切換補充。

[直接載入最長設施路線](https://codefest.yoyo899843.com/station-map?start=b1-wc-nw&destination=b3-civic-red)。此連結設定手動起終點，不產生 QR 掃碼紀錄。

Demo 模擬由 `/station-map?demo=1` 進入，需保留模擬標示。影片、投影片與口頭說明都不能把模擬定位、測試 QR 或模型畫面包裝為已布設、已走查的正式服務。
