# 正式地圖掃碼定位開發指南

本輪依使用者要求，把目的地／搜尋／通行條件／簡明模式／持續掃碼／抵達確認整合到 `/station-map`，保留隊友的樓層、縮放、拖曳、設施圖示與顯示設定。依使用者最新要求，獨立 `/navigation-demo` 頁面與所有入口已移除，舊網址轉回正式地圖。合成資料只留在自動測試 fixture，不顯示為北車實際導航。

2026-11-07 最新使用者決策：指南針先跳過；QR 僅帶點位 JSON。正式地圖按「掃描定位」開啟 TownPass 既有單次原生相機，App 回傳原始字串，由網頁驗證及更新位置。這覆寫本文件前版「必須先選終點、再啟動自訂持續掃碼」的入口；原有合成導航與持續掃描模組保留供獨立測試。

## 操作流程

### 不修改 TownPass 的限制（2026-11-08）

使用者最新指示：TownPass 宿主不可修改。先前為「從 TownPass 首頁直接掃碼開啟 Codefest」新增的原生程式與 patch 已撤回，未發布或安裝。後續僅調整 Codefest 網頁與產碼工具，不新增 App 首頁按鈕、原生 QR 分流或自訂 handler。

核對目前宿主原始碼：內建 `qr_code_scan` 只把掃碼文字回傳給發起請求的網頁，沒有通用的「掃碼後自動開任意服務」分流。[官方繳費掃碼頁](https://taipei-pass-service.vercel.app/fee-payment/scan/)的 `FeePaymentScanView` 將結果視為 Base64 編碼的帳單 JSON，核對既有帳單 ID 後進入繳費結果；一般網址或目前定位 JSON 都不會轉往 Codefest。核對部署資產為 [index-DwgpGSZE.js](https://taipei-pass-service.vercel.app/assets/index-DwgpGSZE.js)，這是該次檢查的版本，非所有發行版的保證。

因此，只換 QR 內容無法達成「從上述繳費掃碼入口直接開啟 Codefest」。不改宿主可沿用下列流程：先從既有服務入口進入 Codefest，再由網頁呼叫內建 `qr_code_scan`。若日後另有支援網址開啟的官方通用掃碼入口，須先核對該入口的協定與實機行為，再評估網址型 QR；不能把手機相機開瀏覽器視為 TownPass 內自動開服務。

1. `/station-map` 沒有 point 時是瀏覽模式，不顯示目前位置；可自由切樓層及選取設施。
2. 按「掃描定位」，以 `flutterObject.postMessage(JSON.stringify({name: "qr_code_scan", data: null}))` 開啟原生掃碼。網頁先監聽回覆，等待期間鎖住按鈕。沒有 flutterObject 的瀏覽器會明示需由城市通開啟。
3. App 掃到 QR 後關閉掃碼頁，回傳 `{name: "qr_code_scan", data: "<QR 原始文字>"}` 的 JSON 字串。data 為 null 是取消；不假設原生會自動開網址。
4. 網頁驗證點位 JSON、場域及版本後，更新當前頁的 `?point=b1-e4&v=1`，不重載整個 WebView。自動切樓層、放大聚焦該點並顯示點位名稱及「您在這裡」。
5. 進入導航模式後，再選目的地，可使用清單、已選標點或七語詞典原型搜尋；保留無階梯、設備排除等硬性條件。
6. 再按「重新掃描定位」更新起點，目的地與限制保留。點選其他設施、看步驟或手動切樓層都不改寫起點。
7. 「退出導航，返回瀏覽模式」清除起點與目的地、移除 point／v，保留其他 query 及 hash。

## 導航中的圖標與重新定位

起點／目前位置與終點就緒後，地圖進入行程聚焦顯示：只保留目前位置、目的地、目前有效轉層指引中的端點，以及所有 `qrcode` 定位點。其他設施標記和未使用的樓梯圖示會隱藏；只改呈現，不刪除任何設施資料或掃碼 anchor。類別篩選在此期間收起，原篩選值保留，且不會遮住 QR 或行程端點。退出行程後恢復瀏覽；以地圖重新挑選起終點時也暫時恢復全部標記。

依使用者最新要求，導航時的「重新掃描定位」改放在導航資訊下方、地圖上方，隨頁面一起捲動，不再浮動覆蓋地圖；移除原本的高度限制、區塊內捲動及浮動列底部預留空間。選點或方向確認對話框開啟時由該對話框取得操作焦點。掃碼由使用者按鈕呼叫既有 TownPass `qr_code_scan`，不會自動重開相機或並行送出掃描請求。收到新定位後保留目的地、無障礙／設備限制，更新目前位置、行程起點和需要的轉層圖標；取消或錯碼保留原行程並允許再掃。即使某設施圖標在導航時隱藏，其定位 QR 仍能讀取並成為新的目前位置。

`navigation-view.mjs` 依既有 session 的有效轉層指引決定保留標記，不新增或推測路徑；QR 邊界示意點沒有已核對路網時，仍如實回報未知通行關係。`StationNavigationRescan.vue` 與原掃碼面板共用同一個 controller，維持 iOS 回覆相容、單一在途與 late-reply 清空規則。原生宿主未修改。

本輪 166 項測試、lint、資產驗證與 production build 通過。實際地圖 Vue 元件的 SSR 渲染驗證導航只留下相關標記及 QR、樓梯圖示過濾、固定掃描列及退出後恢復；實際掃描列元件與 Vue Router 測試驗證 native 請求、取消／錯碼、重複點擊防護、iOS 回覆格式及重新定位時同步起點並保留終點／無障礙設定。瀏覽器連線工具不可用，原生瀏覽器預覽另回報 Computer Use 權限未授予，未做新畫面的瀏覽器／手機視覺檢查，不把 SSR 或模擬回覆視為完整真機驗收。

## 跨樓層提示與手動確認

已有定位入口（QR 或 point 連結）與目的地時，依目前有效連結的第一段顯示設備種類、出發設備名稱及要前往的樓層，例如「經由電梯前往 B2 · 地下二樓」。B1 → B2 顯示「我已下樓」，B4 → B2 顯示「我已上樓」。只對既有可用、方向與端點資料符合的樓層連結提供確認，不把未知區域或 QR 邊界示意點推測成可走路線。混合樓梯／電扶梯若電扶梯方向未核對，另提醒依現場標示確認方向；無階梯過濾維持不變。

按鈕代表使用者回報已到指定樓層。`manualPosition` 記錄此手動進度，`navigationPosition` 提供剩餘連結與地圖聚焦；地圖切到該設備的目的樓層，標示「手動確認位置」，接續下一段。原 `position`、QR 來源與時間仍保留為先前定位點，不假裝又掃了一次碼。瀏覽樓層、看設備詳情不會確認進度，跨層確認也不會自動確認抵達終點。每個顯示中的動作綁定該段 revision token，舊按鈕在重掃、換目的地、變更通行條件、回報設備不可用或完成前一段後均失效；掃碼等待中不可確認跨層。

跨樓層提示、確認按鈕及「重新掃描定位」集中在頁面內同一區塊，完整展開並隨頁面捲動。成功重掃清除手動進度，以新 QR 重算，保留目的地與限制；取消或錯碼保留手動進度。手動進度只存本頁，不寫回 QR 的 point／v；重新整理後仍以最後的定位連結為準。

新增回歸測試涵蓋 B1 → B2 → B4 與逆向轉層、手動與 QR 來源分離、舊動作失效、未知／不可通行連結拒絕、無障礙限制、實際 Vue 按鈕、iOS 回覆及 Router 同步。同步預設地圖入口與導覽說明更新後，174 項測試、lint、資產一致性檢查及 production build 通過。純電扶梯使用明確標示的合成測試資料，未更改正式路網。Android／iOS 新按鈕真機與視覺檢查仍待驗證，TownPass 未修改。

## 網址參數與來源

`http://home.yoyo899843.com:8000/station-map?point=b1-e4&v=1` 是可直接開啟的定位入口；網址參數不是 QR 的內容。point 使用現有 station-points.json 的 ID，省略 v 視為 1；空值、重複 point／v、其他版本、停用或未知 ID 都拒絕，回瀏覽模式並顯示提示。

- 真正原生掃碼：position.source 為 qr，保存實際回覆處理時間 confirmedAt。
- 直接網址／重新整理：source 為 url、confirmedAt 為 null，顯示「由定位連結帶入，請核對現場位置」。不能把開頁時間當成掃碼時間。
- Vue Router 的自身參數同步保留當次 QR 來源與時間；上一頁／下一頁與同頁 query 變更重新套用該入口。
- 「您在這裡」代表最後定位碼或連結提供的點位，不會隨走動自動更新，也不是 GPS、朝向或現場存在證明。

## 模組責任

2026-11-08：Codefest 的「掃描定位」沿用未修改 TownPass 的 `qr_code_scan` 協定。網頁現在於使用時取得 `window.flutterObject`，並在掛載、`flutterInAppWebViewPlatformReady`、`pageshow` 更新可用狀態，處理橋接較晚注入的情況；這些事件不會自行啟動相機。首次連接後固定使用同一通道，保留單一在途、逾時與遲到回覆清空規則；離頁清除事件及結果監聽。沒有 bridge 的普通瀏覽器仍無法使用原生掃碼。

新增 bridge 與 Vue Router 整合測試，驗證晚注入後按鈕可用、按下才送 `{name:"qr_code_scan",data:null}`、成功回覆後更新 point／v、樓層與 QR 來源，以及離頁清理。整合測試的 App 回覆為模擬，不代表 Android／iOS 真機驗收；本輪沒有修改或重建 TownPass。

針對「原生相機已關閉，網頁仍等待且未定位」的回報，已用目前依賴的 `flutter_inappwebview_ios 1.1.2` 原始碼重現回覆格式問題：`WebMessage.swift` 的 `jsData` 把外層 JSON 放進單引號 JavaScript 字串，只處理單引號而未保留反斜線。定位碼本身為 JSON，外層 data 所需的 `\"` 因此被 JavaScript 吃掉，造成網頁收到的外層 JSON 無法解析；原接收器直接忽略，持續等待到逾時。`tests/helpers/ios-web-message.mjs` 只在測試中重現這段 native 序列化，確認正常的定位碼經過該路徑會觸發 SyntaxError。

Codefest 先解析正常 JSON；若失敗，只對 TownPass 固定的 `{"name":"qr_code_scan","data":"..."}` 框架還原內層文字，再交原有 schema／site／版本／本地點位驗證。不執行 QR、JavaScript 或任意網址，也不修改 TownPass／其外掛；Android 與已修復的宿主仍走正常 JSON 解析。定位碼和原生格式的 Vue Router 整合測試涵蓋此路徑，包含錯碼拒絕、取消、定位與結束等待。使用者於 2026-11-08 已回覆「已成功定位」，確認所提供的 B1 電梯範例能由現有 TownPass 掃碼回到 Codefest 完成定位；這不代表新增 32 點或雙平台完整驗收。

接收端另使用官方支援的 `flutterObject.onmessage` 並保留事件監聽，同一原生事件只處理一次；原有 onmessage 會轉交，最後離頁時還原，且不覆蓋其他頁面後續接上的接收器。定位解析的例外會清除等待並顯示七語重試提示，保留舊定位。

## 現有資料的能力邊界

站圖保留原有 89 個設施點與 19 條樓層連接關係，另有 20 個 QR 邊界示意點，共 109 點；已依使用者要求移除月台上的 12 個測試 QR 與附帶圖示。**不是已現地驗證的完整步行 Graph**。目前只提供 zone／connector overview：

- 不捏造同樓層走廊邊，不計算不存在的距離／最快路線／轉彎方向，不承諾未知區域可達。
- 只採 `direction: bidirectional`、端點／樓層／zone 符合的連結；排除 `inferred`、`unverified`。
- 無階梯只採 `type: elevator` 且 `wheelchairAccessible: true`，再排除本次不可用設備；混合樓梯／電扶梯不符合無階梯限制。
- 同 zone 只代表同區域，不代表抵達，也不提供未經證實的走廊指示。
- 完整的「最快／最易懂」逐步導航仍需要實際走廊、轉彎、地標、可及性、設備可用性及現地核對；不以合成 demo 通過當正式北車路線已驗收。
- 真實集合等候區尚無 approved whitelist；不擅自把每個設施點都變成合法、安全的集合等候區。現有合成分享卡不推測映射到正式點。

## QR 契約

沿用獨立 preview namespace，與合成路網分開：

```json
{"type":"taipei_maze_anchor","v":1,"site_id":"taipei-main-map-preview","graph_major":1,"anchor_id":"station_b1-e4"}
```

station_ 後方為本地穩定 point ID；最多 1024 UTF-8 bytes，不帶 URL、座標、樓層或導航文字，僅接受本地存在且未停用的點。這些碼尚未現地布設／核准，正式場域仍需設置授權、資料核對與巡檢。

### 列印測試碼

產碼工具沿用已登錄的 Lincoln Loop python-qrcode 8.2（BSD-3-Clause、固定 wheel hash），只用於建置，沒有新增 Web／手機依賴或線上 QR 服務。

```bash
python3 -m venv .local/qr-tools
.local/qr-tools/bin/python -m pip --isolated install --no-user \
  --index-url https://pypi.org/simple --require-hashes --no-deps \
  -r tools/requirements/station-qr.txt
.local/qr-tools/bin/python tools/generate-station-qr.py
```

輸出至 Git 忽略的 `.local/station-qr/`：

- index.html：按樓層與點位順序排列的預覽／列印表，提供單張 SVG、全部 ZIP 及對照 JSON 下載連結。
