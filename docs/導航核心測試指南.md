# 導航核心測試指南

日期：2026-11-07。此里程碑實作可執行的合成導航流程，不宣稱已完成北車現場導航或 SPEC 全部 P0。

## 開啟方式

```bash
cd app
npm ci --registry=https://registry.npmjs.org
npm run serve -- --host 127.0.0.1 --port 8082
```

開啟 `http://127.0.0.1:8082/navigation-demo`，或從原本 `/station-map` 頁面頂部的「測試導航流程（合成圖）」進入。已有伺服器時不要重複啟動。

TownPass Simulator 的服務入口仍為 `/station-map`，不需再次編譯 Flutter，從頁面連結進入即可。一般瀏覽器可測合成定位；只有具 `flutterObject` 的宿主才提供原生掃碼。HTTP 正常不代表 App bridge 實測通過。

## 這次完成什麼

- 合成 B1／B2 場景：8 個節點、14 條有向邊、樓梯與電梯各一組、3 個目的地、3 個 QR 定位點。
- 圖資料驗證：版本、ID、引用、成本、狀態、可及性、樓層、座標、geometry、connector、文字與方向上下文等核心檢查。
- 使用 adjacency list／min-heap 的 Dijkstra；同成本依 edge ID 序列穩定選路。
- 一般與無階梯路線；封閉、未知狀態及 session 不可用設備排除。無階梯另排除樓梯、電扶梯與未知可及性。
- 新位置確認、目的地選擇、出發朝向確認、逐步指引、到層確認、重新定位、抵達確認與 session 清除。
- 同一份 plan 驅動路線與指令；按下一步不會把位置推測到下一個節點。
- 原生 `qr_code_scan` adapter 與嚴格定位 payload parser。未取得 bridge 的瀏覽器不會假造掃碼成功。
- 原 B1–B4 地圖維持瀏覽用途，不把既有未核對的跨層資料自動轉成可走路網；修正其「已確認可通行」預覽文案，明確揭露示意狀態。

## 可以直接試的劇本

| 劇本 | 操作 | 預期 |
| --- | --- | --- |
| 一般導航 | TEST-A → 確認位置 → 測試廁所 → 確認朝向開始 | 經 B1／B2 樓梯；成本 9，UI 不稱實際公尺 |
| 無階梯導航 | 同起訖改為無階梯 → 重新確認位置 | 改走測試電梯；成本 15 |
| 電梯不可用 | 無階梯路線下，在開發工具模擬電梯不可用 → 重確認 | NoRoute，不退回樓梯 |
| 有效重定位 | 導航中按「我迷路了」→ TEST-B → 確認 | 以 B2 電梯口重算至廁所，舊步驟清空 |
| 新位置無路線 | 導航中改 TEST-X → 確認 | 接受新位置並清除舊 plan；顯示無路線 |
| 取消重定位 | 按「我迷路了」後取消 | 恢復原計畫，不虛構新位置 |
| 取消需求重確認 | 導航中改通行需求 → 取消確認 → 改目的地 | 仍須重確認位置，不能藉選目的地跳過 |
| 已在目的地 | TEST-A → 確認 → 選測試起點 A | 直接進抵達確認，不當成 NoRoute |
| 結束 | 完成或開發工具清除本次測試 | 位置、計畫、目的地與本次故障設定清除 |

這些是可執行人工劇本，不是已有人操作通過的紀錄。

## 原生 QR 測試內容

```json
{
  "type": "taipei_maze_anchor",
  "v": 1,
  "site_id": "synthetic_lab",
  "graph_major": 1,
  "anchor_id": "qr_a"
}
```

其餘 anchor 為 `qr_b2_lift`、`qr_island`。頁面「開發測試工具與 QR 內容」會顯示所選定位點的 payload，可在有權使用的工具中製作測試 QR；本次未新增 QR 圖像套件、外部生成服務或列印資產。

payload 只接受上述五個欄位、UTF-8 上限 1024 bytes，必須匹配 site、major 與啟用 anchor。不接受 QR 自帶座標或任意 URL；掃碼成功後仍需人確認位置。

舊 TownPass bridge 沒有 requestId。adapter 以同一原生物件的共享 channel 串行處理；逾時或 disposal 時保留待清空狀態，重新掛載不能立即把舊回覆當新掃碼。遲到回覆若在沒有 receiver 時遺失，通道可能持續等待，應退出原生功能並重新開啟服務，不以自動重送掩蓋問題。完整文件／原生 bridge 重建無法靠 JS 記憶體證明所有舊請求已結束，因此不宣稱提供端到端 requestId 隔離；原生端協定擴充是後續工作。

## 檔案與介面

| 檔案 | 責任 |
| --- | --- |
| `app/src/navigation/demo-graph.json` | 自製合成資料與繁中測試文案，沒有真實站圖或量測座標 |
| `graph.mjs` | `validateGraph(graph) -> string[]`，拒絕不合法核心資料 |
| `route.mjs` | `planRoute(graph, request)`，回傳 success／InvalidGraph／NoRoute 等結果 |
| `qr.mjs` | `parseAnchor(payload, graph)`，只查本地 anchor |
| `session.mjs` | `createSession(graph)`，管理位置、plan、步驟與確認流程 |
| `bridge.mjs` | `createQrBridge(nativeBridge)`，串行掃碼、逾時與清理 |
| `NavigationDemoView.vue` | 導航測試操作、錯誤與恢復畫面 |
| `NavigationDemoMap.vue` | 同層 geometry 疊圖；不跨圖畫線 |
| `app/tests/*.test.mjs` | Node built-in test runner，無新增測試依賴 |

目前沿用隊友匯入的 JavaScript／Vue CLI 工具鏈，核心採 `.mjs`，不宣稱已有 TypeScript 編譯檢查。未新增第三方依賴。此 assembled fixture 將各組資料放在同一檔供測試；正式分檔包仍依 SPEC 第 8–9 節，由載入器組成同一 snapshot。

`Route` 不含 instructions；`Session` 成功建立 `NavigationPlan` 後才一起發布地圖與指令。出發與跨層出口缺少精確 orientation context 時，進入 guidance_unavailable，不猜左右。

## 與地圖組接軌

| 目前地圖資料 | 導航需要的補充／轉換 |
| --- | --- |
| 大寫樓層、連字號 point ID | 建置時轉為 SPEC 的穩定小寫底線 ID，保存一對一 mapping 並更新引用 |
| 單一設施 point | 分開 POI 與實際可達 node；不能只看圖示就認定能走到 |
| 區域間 connection | 明確 connector 與每一有向 edge；不同設備種類分開核對 |
| 整個區域視為互通 | 補同層走道、決策點與折線 geometry；不可把區域內所有點直接全連 |
| `wheelchairAccessible` 布林 | 補 step_free／wheelchair_passable 的 yes／no／unknown 與證據 |
| 中文 name／description | name_key／text_key 與七語 catalog；保留現場中文原文 |
| 示意點位 | source_ids、verification_status、核對日期及適用範圍 |
| 尚無 QR／朝向 | anchor 與人工方向 guide；跨層出口也要核對 |

此表是交接契約，不是已實作的自動轉換器。真實資料應先另建 `field_verified_demo` 包，逐條核對；目前 validator 會拒絕將 synthetic 元素直接換模式當成 field_checked。不要在合成圖上標「已現場核對」，也不要為了找到路線放寬驗證模式。

## 離線詞典搜尋與易讀模式增補

地圖頁與導航測試頁已加入相同搜尋核心。地圖只查既有設施位置，不會使用區域 BFS 冒充完整步行導航；導航頁需明確選擇設施與條件，再走位置確認與原有 plan 流程。

搜尋支援七語 draft 種子詞、全形正規化、OSA 錯字建議與有限條件。最近、未知否定／比較與未理解片段要求澄清；不由名稱推定設施可及性，不解除原有較強條件。合成廁所的 accessible_facility=true 僅用於測試「accessible toilet → stepFree → 電梯」整合。

易讀模式在行進、抵達確認與完成時收起非必要操作區，保留單一步驟與恢復；地圖可自行展開。此切換不變動 session、位置、目的地或限制，不代表已完成使用者可用性測試。

模型候選、完成狀態與新增手機聊天需求見 [AI 功能規劃](./Taipei_Maze_AI_Features.md)。

最新搜尋增補驗證：43 個核心測試通過，包含 alias／錯字／否定、編號保護、draft 詞典隔離、限制合併與搜尋至電梯路線整合。全專案 lint／build 通過；人工畫面、翻譯、真機與離線驗證仍不列 PASS。
