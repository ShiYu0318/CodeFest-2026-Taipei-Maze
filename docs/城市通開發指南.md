## 取得與建置 TownPass

以下在**獨立宿主 checkout** 執行，不要把外部 repo 的 `.git` 複製進本 repo，也不要把本 repo 改為另一個 Git 根。此專案目前沒有 Flutter pubspec，不應在根目錄直接跑 Flutter 指令。

### 首次取得

```bash
git clone https://github.com/taipei-doit/TownPass.git
cd TownPass
git rev-parse HEAD
cat .fvmrc
fvm install
fvm flutter --version
fvm flutter doctor -v
fvm flutter pub get
fvm dart run build_runner build
fvm flutter devices
fvm flutter run
```

先 clone 當時最新 main，再記錄確切 commit；本指南核對快照如上，不代表以後的 main 永遠不變。要重現本指南快照，可在乾淨 checkout 使用 `git switch --detach c8e5d4d3f8f699f3d9d6cd68e129ed4da12037b3`，開發前另建工作分支。不要對有未提交修改的 checkout 直接切換或清除。

未使用 FVM 可移除每行開頭 `fvm`，但須確認 `flutter --version` 符合 3.47.6。不要在本 repo 根目錄新增 `.fvmrc` 假裝它本身是宿主；版本屬於 TownPass checkout。

### build_runner 的用途

產生 `lib/gen/assets.gen.dart` 及 JSON 序列化程式。新增 `assets/svg/icon_taipei_maze.svg` 後重跑，才會產生對應的 `Assets.svg.iconTaipeiMaze`。2026-11-07 實測目前 lockfile 的 build_runner 已移除並忽略 `--delete-conflicting-outputs`，因此不再傳入 PDF 舊範例中的參數。先保護未提交工作並確認哪些是生成檔。

本機實測：`flutter_inappwebview_ios` 仍需 CocoaPods，不能只靠 Swift Package Manager；已安裝 CocoaPods 1.17.0。工具版本、模擬器及驗證限制見 [本地測試環境](./測試環境.md)。

### 建置失敗的檢查順序

1. 確認 cwd 為 TownPass、commit、`.fvmrc`、FVM Flutter／Dart 是否一致。
2. 檢查 Java、SDK、Xcode、簽章及裝置狀態；用 `fvm flutter doctor -v` 保存必要摘要，不貼 key。
3. 確認 pub get 完成，再產生程式碼；缺 `assets.gen.dart` 通常不是要手寫補檔。
4. iOS 首次可能下載 Swift Packages；套件仍使用 Pods 時依上游實際流程處理，不先刪 Podfile。
5. 若確定是舊快取／產物問題，可在宿主保護工作後 `fvm flutter clean`，重新 pub get／build_runner；不要用清理掩蓋版本錯誤。
6. 保存完整錯誤、命令與工具鏈資訊，再定位第一個根因，不一次升級全部依賴。

## 加入 Taipei Maze 服務

### 最小修改

## WebView 雙向溝通

來源：PDF 第 17–21 頁；核對 `TPWebMessageListener`、`TPWebMessageHandler`、官方 Web composables 與 QR Controller。

### 協定

```text
微服務網頁
  JSON.stringify({ name, data })
  → window.flutterObject.postMessage(...)
  → TPWebMessageListener 依 name 找 Handler
  → 原生功能（本案是掃 QR）
  → replyWebMessage({ data })
  → flutterObject 的 message event
  → JSON.parse(event.data) 得 { name, data }
```

雙向都是 **JSON 字串**，不是傳 JS object，也不是一般瀏覽器的 `window.postMessage` 協定。普通 Chrome 沒有 `flutterObject`；須顯示「需在城市通開啟」或明確 Demo adapter，不得把 mock 結果假裝成實機掃碼。

### 已核對的內建名稱

| name | 用途／回覆特性 | Taipei Maze 是否需要 |
| --- | --- | --- |
| `qr_code_scan` | 打開原生掃碼，結果在 `data`，現有 Controller 回字串或取消 null | P0 使用 |
| `location` | GPS position 或失敗時非 position 值，不保證是統一錯誤物件 | 不使用作室內定位 |
| `userinfo` | Mock AccountService 的帳號資料 | P0 不請求 |
| `deviceinfo` | 裝置資訊 | 僅必要平台診斷時評估，不主動收集 |
| `notify` | 通知；現有成功分支不保證有 reply | P0 不需要，不寫成必定回 ACK |
| `open_link`、`launch_map` | 開連結／地圖，需個別核對輸入與回覆 | 不拿來執行 QR 自帶網址 |
| `phone_call`、`1999agree` | 電話與既有同意流程 | 不是本案導航必要能力 |

不要把功能中文名自行猜成 `scan`、`getUserInfo` 或 `notification`。本案只發已確認的最小能力。

### 網頁端生命週期示例

下面是文件用最小示例，只表示訂閱、驗證與清理位置；完整產品還須實作逾時、去重、權限及取消狀態。

```javascript
const bridge = window.flutterObject;
if (!bridge) {
  showOpenInTownPassMessage();
} else {
  const onReply = (event) => {
    let reply;
    try {
      reply = JSON.parse(event.data);
    } catch {
      return;
    }
    if (!reply || reply.name !== 'qr_code_scan') return;
    if (reply.data === null) {
      handleScanCancelled();
      return;
    }
    if (typeof reply.data !== 'string') {
      handleUnexpectedScanReply();
      return;
    }
    validateAndConfirmAnchor(reply.data);
  };
  bridge.addEventListener('message', onReply);
  bridge.postMessage(JSON.stringify({ name: 'qr_code_scan', data: null }));
  // 頁面真正卸載時：bridge.removeEventListener('message', onReply)
}
```

先訂閱再送出，避免回覆先到。每個服務頁只註冊一個 receiver，由 adapter 分派，卸載移除同一個函式；不要每個按鈕或子元件各自加 listener。官方 Vue `useConnectionMessage.ts` 與 `useHandleConnectionData.ts` 可作行為參考，本案不必照搬 Vue 依賴。

### 沒有 requestId 的限制

上游 `{name,data}` 外層沒有 requestId、統一 error schema 或保證每種 handler 回覆。本案在 Web 端只能自行追蹤 session，不得假設 App 會回傳自加的 requestId。

- 同一時間最多一個掃碼請求，按鈕 disabled，收到成功／取消才釋放。
- 工程預設 60 秒顯示等待過久提示，**不能因 timeout 就自動重送同名請求**。
- timeout 或 Web 端取消後，該舊請求仍可能回覆；將通道標為 waiting_for_drain，丟棄其遲到回覆後才可新掃。若一直沒回覆，提示關閉並重新進入服務，不能把下一份遲到結果當成新定位。
- 頁面已卸載後所有回覆無效。新頁面必須確認宿主舊掃碼頁已退出；無法保證時，透過小幅自訂 handler 加可驗證 correlation ID，再測雙平台，不在舊協定上假造保證。
- 扫碼結果還是未信任輸入，需依 SPEC 的類型、大小、site、版本及 anchor 檢查；不能直接開 URL 或採用 payload 中自帶座標。

### 擴充 handler

只有現有能力確實不足才擴充。繼承 `TPWebMessageHandler`，設定唯一 `name`，實作 `handle`，再加入 `_cachedMessageHandlers`。使用 `replyWebMessage` 包回相同 name；自訂新協定才可設計 requestId／error。

原生端必須驗證 `sourceOrigin`、`isMainFrame`、允許的 HTTPS／本地 bundle origin 與能力白名單。現有 listener 接收這些資訊，不等於已替本案完成安全過濾。不要把橋接註冊到任意外部頁面，也不要為方便而全域授權定位或任意 scheme。

## WebView 生命週期與雙平台

來源：PDF 第 16 頁；本案補充對 QR／語音競態的要求。

- 真正離開服務時移除 message listener、清掉 timer／observer、停止音訊，讓宿主釋放該 WebView；不要留下多個 headless／keep-alive 實例。
- 暫時背景與「原生掃碼頁覆蓋 WebView」不是同一種卸載。掃碼過程可保留 pending listener；不可在 visibility hidden 時直接移除 listener 或宣告掃碼取消，否則收不到正常回覆。
- 背景先停語音與非必要動畫；回前景確認後續播，不自動推進導航。
- iOS 預設可能阻擋 popup；Android 也需實作對應處理。P0 避免 `window.open`、付款式跳窗與依賴新視窗流程。
- HTMLAudioElement 的 `play()` 可能因使用者手勢政策被拒絕。提供明確「播放」按鈕，不能不斷自動 retry。
- App 返回、網頁返回與關閉整個服務分開測試，導航中離開要可理解；切地圖不改位置。
- 用 Chrome DevTools 看手機版面只是第一層，必須從 Android／iOS 的城市通實際開啟測橋接。未測 iOS 要明確標未測，不能拿 Android PASS 當跨平台保證。

### P1 多目標規劃與離線搜尋

最新補充見 [SPEC 第 21 節](./SPEC.md#21-多目標認知路線與離線目的地搜尋)：Dijkstra 搭配多路徑枚舉產生候選，比較最短／有時間模型才可用的估計最快，以及規則式易懂路線。無障礙與方向限制先過濾，排序不能放寬。

## 七語與語音製作

七語是使用者最新要求，優先於 PDF 的一般範例及原提案三語版本。詳細契約見 SPEC 第 13–16 節。

1. 一份中文主 catalog＋穩定 key，涵蓋畫面、錯誤、POI、地標與指令。
2. 開發期使用已核准、非中國來源翻譯服務批次產六種外語草稿；人工核對方向、樓層、否定與站內標示。
3. 24 個固定導航句 × 7 語＝168 個核心音檔；逐句聽檢、檢查輸出再散布權與來源。
4. 文字產生 `web/public/assets/i18n/{locale}.json`，不再為我們的網頁產生 Flutter ARB。宿主若另外做語系修改，再依上游方式處理。
5. 預生成 MP3、字型與地圖打包，HTMLAudioElement 用 locale＋sentence_id 播放，切語言時中止舊音訊。
6. 不能以 `speechSynthesis` 或裝置未知聲音包替代已審查七語音檔，也不即時呼叫 TTS API。

Microsoft 全球 Azure 翻譯／Speech 是 SPEC 的候選製作方案，不代表已採用、付費、通過來源審查或確認所有輸出可隨 AGPL 專案散布。未核准時採具可追溯權利的真人翻譯／錄音；不能偷偷換中國模型、代理或匿名免費網站。

## AI 與來源限制

來源：PDF 第 46–52 頁，加上使用者更嚴格要求。

開發期可用已核准雲端 AI 協助企劃、寫碼、除錯、資料整理與固定素材製作；實際引用網址、欄位、LICENSE 都要查證。**本案執行期不需要 LLM**，也不新增 runtime 翻譯／語音推論服務。

## 部署與離線

來源：PDF 第 53–58 頁；平台、費用與服務條款會變動，實際部署前再次核對。下列是文件步驟，不是本次已部署。

### 靜態前端

必須 HTTPS，可用經核准的 Firebase Hosting、GitHub Pages 或其他非中國來源靜態託管；框架 build 輸出何處就部署何處，不因範例 Vite 用 dist 而假設所有工具相同。本案目標輸出 `web/dist/`，來源與資料不依賴私有 CDN。

Firebase 範例流程：安裝官方 CLI、登入並選正確專案，在 web 子專案 init hosting，public 指向 dist，SPA fallback 依路由方案設定，不覆蓋已建置的 index，完成 build 後 `firebase deploy --only hosting`。建立帳號／付費及對外發布均須沿用使用者已授權範圍，不能把文檔範例當成授權。

部署後將實際網址填入 `destinationUrl`，從城市通開啟，測路徑 base、資產 MIME、音訊、返回與橋接。用 hash routing 可減少 SPA 伺服器重寫需求，是否採用仍須依實作鎖定。

### 後端選配

本案 P0 不需後端，既有 hello-world compose 不當作完成產品部署。日後若有後端，可提供 Dockerfile、PORT 設定與來源清單，並選非中國部署區域。Cloud Run 的 `--source` 可由雲端建置並使用 Artifact Registry；不要沿用舊 `gcr.io` 流程。

PDF 的 asia-east1 為臺灣區域建議；實際延遲、費用、免費額度及公開設定需量測與確認，不承諾「一定最低延遲／一定零費用」。CORS 限定正式前端 origin，不為方便把帶憑證 API 設成任意 origin。機密保留伺服器，TDX client secret 不能包在前端。

### 三個不同離線層級

| 模式 | 代表什麼 | 不能混稱 |
| --- | --- | --- |
| 開頁後斷網 | 所需 Graph／文字／音檔已載入，該次 session 不再需要 API | 不代表關掉重開仍可用 |
| 已預載後離線重開 | 該 WebView 對完整資產有經驗證持久快取或 Service Worker | 不代表全新安裝、無快取可首次離線開 HTTPS |
| 宿主內嵌靜態 bundle | 將完整 web build 封裝到 App 並實作可信本地載入與橋接 | 不是 TownPass 原本只填 destinationUrl 就自動完成的能力 |

本版 SPEC 保留原先最強的「新安裝首次離線」產品目標，因此要完成第三種模式，新增最小宿主本地 bundle loader 並驗證 Android／iOS；它是待實作的 P0 工作，不能默默降成只有第一種。遠端 HTTPS 版保留為一般服務入口；嵌入包與遠端版對應相同 package hash，避免展示不同路網。

宿主本地載入需確認 origin、asset path、音訊 MIME、base path 與 bridge 權限；不以全域開啟任意 file access／JavaScript origin 來解決。若時程無法完成，要標未達離線 gate，不虛構已完整支援。
