# 手機聊天與語音開發指南

本輪實作浮動聊天、Google Gemma 3 1B INT4 裝置端推論、原生語音草稿與手機內模型安裝。iPhone／Android 共用 Vue 介面與 Flutter 橋接；Swift／Kotlin 分別呼叫官方 LiteRT-LM。模型實際推論速度、品質、發熱與麥克風效果仍須真機驗證，建置成功不能代替這些結果。

## 回答方式：先查車站資料，模型只是選配

小幫手不需要模型也能回答（`app/src/chat/answers.mjs`）。順序如下：

1. **找設施**：問題裡有七語的設施名稱或常見說法（例如「廁所」、toilet、Nhà vệ sinh、トイレ、화장실），就從 `station-points.json` 列出真實的設施，最多 5 處。使用者所在的樓層排在前面，問句裡有樓層時（例如「B2 的廁所」）只列那一層。每一處都附「在地圖上看」，點下去會收起聊天、切到地圖並聚焦那個設施（`station/map-focus.mjs`）。樓梯類設施刻意不列，避免對「不能走樓梯」的人列出樓梯。
2. **使用方式**：迷路、出口、請人幫忙、無障礙、掃碼、換語言、字太小、隱私等主題，用使用者的語言給固定答案。答案裡的按鈕名稱和介面一致。出口資料還沒建置，會照實說明，並引導使用「給站務人員看」。
3. **打招呼與道謝**。
4. 都對不上時，有裝置端 Gemma 就交給模型。提示詞會指定回覆語言，並附上 App 的事實，不准編造出口、路線或即時狀態。沒有模型時，就說明「我能回答哪些事」。

因此一般瀏覽器、還沒下載模型、或完全離線時，小幫手都能回答找設施與使用方式的問題。狀態列顯示「站內問答 · 離線可用」；只有在城市通 App 內，才會出現「安裝 AI 模型（選配）」的提示。

## 使用方式

1. 重建並安裝新版 TownPass，選「CodeFest 測試環境」。內建網頁由手機本機 `127.0.0.1:8766` 提供，不需要電腦的 Vue server。
2. 點右下角「小幫手」，可收合、清除對話、停止回覆。中日韓輸入法的候選確認 Enter 不送出；一般 Enter 送出，Shift Enter 換行。
3. 尚無模型時，點「安裝 Gemma 3 聊天模型」。原生畫面內建 Gemma 使用條款、禁止用途政策與 Notice 全文，不需要 Hugging Face 帳號或 Token。
4. 勾選同意條款後按「同意並下載模型」。App 內建的 `assets/gemma_release.json` 固定官方來源、revision、大小與 SHA-256，只從 `https://home.yoyo899843.com/models/` 下載；`available` 為 false（尚未發佈）時按鈕停用，不改用其他鏡像。
5. 584,417,280 bytes 權重串流下載、比對內建 SHA-256 後才安裝，條款、政策與 Notice 一併寫入模型目錄。原生 runtime 載入時再核對固定雜湊。
6. 選語音語言，主動點「語音輸入」才申請權限並錄音。最長 30 秒；「完成錄音」先停止收音，再等 final 結果，最長等 3 秒。辨識文字加入草稿，確認後手動送出。

一般瀏覽器可看到聊天視窗，但不假裝已有原生模型或語音。遠端 HTTP 正式站可顯示元件，但 AI 橋接拒絕；使用內建手機網頁包，或部署指定 HTTPS 網站後更新宿主配置。既有 `http://home.yoyo899843.com:8000/` 地圖與導航流程保留。

| 模型檔 | `gemma3-1b-it-int4.litertlm`，584,417,280 bytes |
| Runtime | [Google LiteRT-LM](https://github.com/google-ai-edge/LiteRT-LM/tree/v0.19.1)，0.19.1，Apache-2.0 |

| Dart 雜湊／路徑 | Google Dart `crypto` 3.0.7、Flutter `path_provider` 2.1.6，BSD-3-Clause；原宿主已間接使用，本輪改直接宣告 |
| 授權 | 權重採 [Gemma Terms](https://ai.google.dev/gemma/terms)，不因作品 AGPL 自動變 AGPL；權重、Token 不提交 repo |

Google 清單列出模型最低 4 GB 記憶體，這是選型依據，不保證同時運作城市通／地圖後每款 4 GB 手機皆順。安裝建議預留 2 GB 儲存空間；兩平台先採 CPU、context 4096、最多 256 output tokens。提示文字的 UTF-8 上限 3500 bytes，最多保留最近四則短對話；畫面保留最多約 20 則且僅在記憶體。聊天不能呼叫路線／定位工具，回答仍可能不正確，導航以已驗證的路網與指示為準。

## 語音邊界

- iOS 使用 Apple `SFSpeechRecognizer`，先確認 `supportsOnDeviceRecognition`，再強制 `requiresOnDeviceRecognition = true`。不支援就保留文字，不退回網路辨識。
- Android 要求 API 31+ 的 `createOnDeviceSpeechRecognizer`。除可用性外，需能識別平台的 on-device provider 為 Google 系統套件；未知 OEM provider 拒絕。`EXTRA_PREFER_OFFLINE` 只是附加提示，不是離線保證的唯一依據。
- 七語選項：繁中、英、越、印尼、泰、韓、日。選項存在不等於手機已安裝全部語言的離線辨識；實際不支援會提示改打字。
- 不使用 Web Speech／遠端辨識、不保存錄音。關閉聊天、頁面背景、原生 WebView disposal／主文件 navigation、App 背景，都會停止錄音與取消推論；釋放模型。
- 終端使用者不輸入任何帳號或 Token；下載只允許 `https://home.yoyo899843.com`（預設 443 port、無 userinfo），不跟隨轉址到其他主機。每次安裝有獨立暫存目錄，取消後只清自己的檔案。

## 手機內建網頁包

`tools/package-townpass-web.py` 將 Vue production dist（不含 source map／權重）轉為含檔案 SHA-256 的 gzip bundle。宿主 `CodefestBundleServer` 僅綁 `InternetAddress.loopbackIPv4:8766`，只讀 App asset，不提供檔案系統或 API；已知頁面返回 index，靜態檔精確查表，僅 GET／HEAD。CSP `connect-src 'none'` 禁止網頁發送網路資料；原生下載不受此網頁策略影響。

Port 被占用會停止啟動並顯示載入失敗，不直接開啟占用者內容。網頁更新需要重建 App 包；「CodeFest 即時開發預覽」則仍連接電腦 `127.0.0.1:8082`，適用模擬器。首次安裝的內建地圖頁可本機載入，Gemma 權重與系統語音語言包仍需先備妥，未以此宣稱整份 SPEC 的離線能力已通過。

```bash
npm ci --prefix app
bash scripts/townpass-env.sh bundle-web
bash scripts/townpass-env.sh deps
bash scripts/townpass-env.sh build-ios --no-pub
```

`build-ios`、`run-ios`、`deps` 會先重建網頁包。另有開發用 `tools/provision-gemma.py --help`，在本機環境設定 HF_TOKEN 並自行接受授權後，核對同一官方檔案並可安裝到模擬器或可 debug 的 Android 私有容器；不要將 Token 貼入聊天或提交。

## 橋接契約

Web 發送 `{name:"codefest_ai", data:{requestId,action,...}}`，requestId 是 32 位隨機十六進位。回覆包含相同 ID 與 `status`；舊／逾時／取消回覆不採用。動作包括 status、setup、generate、voice、stopVoice、cancel、unload。status 不請求權限、不開始推論；setup 只開啟原生安裝畫面，不收集任何憑證。輸入上限／語系／main-frame／origin 在 Flutter 層再檢查。

允許來源：`http://127.0.0.1:8766`（內建）、`http://127.0.0.1:8082`／`http://localhost:8082`（開發）、`https://home.yoyo899843.com`（尚需實際 HTTPS 部署）。**不允許遠端 HTTP AI**，避免網路竄改者利用已取得的麥克風權限。橋接並非通用執行任意 native method 的 API。

## 建置與驗證

- iOS 官方 binary 僅含 arm64 實機／模擬器。Runner 對 iphonesimulator 排除 x86_64；Intel Mac 無法藉此測試 AI 模擬器。Swift SPM 固定版本及 resolution 已保存。
- Android main manifest 明確加入 INTERNET；Network Security Config 預設拒絕 cleartext，只對 loopback 與使用者指定的現有 HTTP 導航網域放行。AI 另由 origin gate 拒絕遠端 HTTP，不因網路設定放行就啟用麥克風。
- Android CI 使用 GitHub Ubuntu runner 已安裝的正式 NDK `29.0.14206865`；舊上游 `29.0.13113456` 會觸發未接受的 preview license，這是首次 CI 失敗原因。不自動接受預覽授權，也不在使用者電腦安裝 SDK。
- CI 從固定 TownPass commit 套 patch，再建立網頁包、產生原宿主 codegen、跑新增測試及建置 APK；不下載 Gemma 權重、不需要 Token 或簽章私鑰。
- 宿主原有 Counter smoke test 與目前 MyApp 不符，本輪沒有刪除或宣稱修好；新增測試有獨立命令。

待完成的實測：合法模型權重實際下載、兩平台手機推論／記憶體／熱量、實體麥克風與最終字詞、所有語言包、鍵盤／螢幕閱讀器及 App 返回／背景。沒有授權帳號與實機前，這些項目維持 not_run。

## 模型發佈流程（團隊）

1. 團隊成員以自己的 HF 帳號接受 Gemma 條款，執行 `python3 tools/prepare-gemma-release.py --accepted-gemma-terms`，在 `.local/gemma-release/public` 產生權重、receipt、條款、政策與 Notice。
2. 將這五個檔案上傳至 private repo 的 draft release `model-gemma3-1b-it-int4-1325ae366d31`（已存在）。
3. 在 main 手動執行 GitHub Actions「Publish approved Gemma model」：self-hosted runner 以 `GITHUB_TOKEN` 列出 releases（draft 只對具 push 權限的 token 可見，故 workflow 需 `contents: write`），核對大小、SHA-256、receipt 與條款全文後，才將檔案放入 `.models`，由 nginx 的 `/models/` 白名單路由對外提供，經 Cloudflare Tunnel 走 HTTPS。
4. HTTPS 上線後執行 `python3 tools/prepare-gemma-release.py --activate`，下載完整檔案驗證雜湊並把 `integration/townpass/gemma-release.json` 改為 `available: true`，再重建 App。

公開提供權重屬 Gemma 條款的再散布：必須附條款全文、禁止用途政策與 Notice，並在條款中轉達使用限制。實際 HTTPS 發佈、`--activate` 與真機一鍵下載尚未實測，維持 not_run。
